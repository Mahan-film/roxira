# Security Policy

## Reporting a vulnerability

Please report security issues privately by email to **[REDACTED]**.
Do not open a public GitHub issue for a suspected vulnerability.

Include enough detail to reproduce the problem: the affected surface, steps to
reproduce, impact, and any proof-of-concept. If you would like to encrypt your
report, ask for our public key in the same email before sending details.

## Supported surfaces

We accept reports for production surfaces we operate:

- `ghazihoushmand.ir`
- `roxira.ir`

## Out of scope

The following are not covered by this policy:

- Findings that require a compromised device, browser extension, or account.
- Denial-of-service from volumetric traffic or resource exhaustion.
- Missing security headers or best-practice hardening with no demonstrable impact.
- Vulnerabilities in third-party services we do not control.
- Social engineering, spam, or physical attacks.

## Response target

We aim to acknowledge a report within **7 days**. Valid reports are triaged and
fixed as quickly as severity warrants, and we will keep you updated on progress.

## Secrets

Never paste credentials, tokens, API keys, customer data, or case data into a
GitHub issue, pull request, or public discussion. Share secrets only through the
private reporting channel above.
