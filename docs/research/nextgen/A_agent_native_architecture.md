# Agent-native architecture radar — 2026-10-01

## Bottom line

Roxira should make its Factory state durable in its existing Postgres database and treat GitHub Actions as a bounded executor, not an agent-runtime. Adopt spec-first work, a planner/worker/verifier contract, trusted portable skills, and hardened MCP now. Trial DBOS only for one FastAPI-owned durable flow. Keep A2A and AG-UI behind small adapters; skip heavyweight workflow platforms and agent meshes on the single 15 GB host.

All sources below were checked on **2026-10-01**. “UNVERIFIED” means the primary source did not substantiate the detail.

## 3. Team patterns that merit use

| Item | What it is / maturity / license | Fit / cost | Verdict and first small task |
|---|---|---|---|
| Planner → worker → verifier, with an artifact blackboard | A lead decomposes bounded work; isolated workers produce evidence/PRs; an independent verifier checks explicit acceptance criteria. Anthropic reports this orchestrator-worker pattern in its production Research system; Berkeley’s 2026 work finds environments and verifiers are a primary capability axis. This is a pattern, not a package; no license. | **5/5.** Matches Roxira’s existing executor/reviewer separation. Extra cost is controlled model calls. | **ADOPT.** Require every Factory task to carry: spec version, owned paths, max diff, commands, expected artifacts, cost cap, and stop conditions. Workers write only append-only artifacts; the verifier receives the spec, diff, and test evidence—not the planner’s persuasive prose. |
| [GitHub Spec Kit](https://github.github.com/spec-kit/) | Agent-neutral spec-driven process: Specify → Plan → Tasks → Implement → Converge, with versioned Markdown artifacts and offline/firewall support. 138k stars; docs updated 2026-09-28; MIT; 38 integrations listed. | **5/5.** Portable across Codex/OpenCode and works with GitHub issues/PRs. CLI/package cost $0. | **ADAPT.** Pilot its artifacts, not a wholesale install: map one approved Factory brief to `spec.md`, `plan.md`, `tasks.md`, and `acceptance.md`; make CI reject implementation when acceptance criteria or owned-paths are absent. |
| [Kiro specifications and steering](https://kiro.dev/docs/) | Proprietary multi-surface agent environment using requirements/design/tasks, steering, hooks, permissions, skills, and sub-agents. Licensing, Iran availability, and pricing are **UNVERIFIED**. | **2/5.** Useful ideas but adds a vendor harness and cloud dependency alongside Codex/OpenCode. | **SKIP.** Borrow only its repository-local “steering” idea: keep concise, versioned policies in Roxira rather than adopting the product. |

Do not use a free-form shared “blackboard memory.” The durable blackboard should be structured, append-only, and reviewable: brief, approved spec, task DAG, source citations, model/run metadata, test artifacts, PR URLs, verifier result, and deployment result. Workers should not share writable worktrees or mutable prompts.

## Ranked top-8 adoption list

1. **Durable Factory ledger:** Postgres run/step/artifact records plus idempotent GitHub Action step claimers.
2. **Spec-first gate:** adopt a minimal Spec Kit-shaped `spec → plan → tasks → acceptance` artifact chain.
3. **Planner/worker/verifier contract:** ownership, budgets, stopping rules, independent verification, and append-only evidence.
4. **Trusted Agent Skills library:** portable internal `SKILL.md` packages, audited scripts only, progressive loading.
5. **MCP containment:** allowlist, data classification, OAuth/audience checks for remote servers, and no broad credentials.
6. **Internal capability-token broker:** per-run, short-lived, path/tool/budget-scoped authority with auditable grants.
7. **DBOS durability spike:** one synthetic FastAPI research-and-approval workflow with crash/restart evidence.
8. **A2A/AG-UI compatibility seams:** static internal Agent Card/task schema first; then a read-only Persian run-progress UI.
