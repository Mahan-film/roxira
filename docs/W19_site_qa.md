# W19 — ممیزی و رفع باگ دکمه‌های ghazihoushmand.ir

روش: بررسی کد (هدر، چت، مودال اشتراک، میدل‌ور دامنه) + خواندن روت‌های واقعی بک‌اند
(`smartjudge_module.py`) برای تطبیق قیمت/plan_type. اجرای زنده Playwright از داخل
سندباکس این نشست ممکن نشد (لانچ Chrome با خطای مجوز mac سندباکس و DNS محدود شده‌اند)؛
لینت/tsc محلی و خواندن مستقیم کد جایگزین شد. `next build` هم فقط به‌خاطر محدودیت
سندباکس (Turbopack نیاز به bind کردن پورت برای پردازش CSS دارد) شکست خورد، نه به‌خاطر کد.

## جدول عناصر

| عنصر | وضعیت قبل | اصلاح |
|---|---|---|
| مودال «افزایش موجودی» (طرح ماهانه/سالانه + ۳ بسته توکن) | همه دکمه‌ها فقط یک toast محلی نشان می‌دادند؛ هیچ فراخوانی به `create-invoice` نبود؛ قیمت‌ها (`$9`/`$90`/`$5`/`$20`/`$60`) در کلاینت جعلی بودند و هیچ plan_type واقعی نداشتند | بازنویسی `subscription-modal.tsx`: قیمت واقعی از `GET /payments/pricing-matrix` (فقط `SINGLE_DRAFT` و `VIP_MONTHLY_PRO` که در سرور وجود دارند)؛ کلیک واقعاً `POST /payments/create-invoice` را صدا می‌زند و به درگاه زیبال هدایت می‌کند؛ ۳ بسته توکن که در سرور plan_type ندارند «به‌زودی» و غیرفعال شدند |
| نیاز به تلفن/ورود برای پرداخت | اگر کاربر لاگین نبود، مودال قدیمی اصلاً تلفن نمی‌گرفت و خطای ۴۰۰ سرور دیده نمی‌شد | فیلد شماره تلفن inline اضافه شد؛ در صورت نبود توکن JWT، پیام سرور («ورود یا شماره معتبر لازم است») مستقیماً نمایش داده می‌شود |
| دکمه «افزایش موجودی» → داده کاربر | `onTopUp` محلی/بدون اتصال به سشن واقعی بود | از `useAuth()` واقعی (`accessToken`, `user.phone`) تغذیه می‌شود |
| لینک ناوبری «محاسبه‌گر قضایی و خسارت» (`/damages`) | میدل‌ور به‌جای صفحه واقعی، به ریشه `https://roxira.ir/` ریدایرکت می‌کرد و چون از طریق `next/link` (ناوبری کلاینتی SPA) کلیک می‌شد، fetch میان‌دامنه‌ای Next.js خطای شبه-CORS در کنسول می‌داد | میدل‌ور مسیر را حفظ می‌کند (`roxira.ir/damages` نه `roxira.ir/`)؛ لینک هدر برای مسیرهای برون‌دامنه‌ای از `<a>` معمولی به‌جای `<Link>` استفاده می‌کند تا ناوبری کامل صفحه انجام شود، نه fetch کلاینتی |
| ۸ چیپ اقدام سریع/حقوقی (لایحه دفاعیه، دادخواست، شکواییه، اظهارنامه، استراتژی پرونده، اعاده دادرسی، صلاحیت دادگاه صلح، آرای وحدت رویه) | بررسی کد: همه به `handleSendMessage` با prompt درست وصل بودند؛ باگی در کد پیدا نشد | بدون تغییر؛ تست دودی جدید (بدون کلیک واقعی، بدون هزینه LLM) اضافه شد تا مطمئن شویم هیچ‌کدام غایب/غیرفعال نیستند |
| ورود/ثبت‌نام با پیامک (OTP) | بررسی کد: `LoginModal` کامل به `judge-auth-client` و `AuthProvider` وصل است و end-to-end کار می‌کند | بدون تغییر؛ تست باز شدن مودال (بدون ارسال واقعی پیامک) اضافه شد |

## خارج از محدوده این PR (نیاز به تصمیم یا دیپلوی)
- اجرای واقعی Playwright روی همه صفحات (`/services`, `/technology`, `/about`,
  `/contact`, `/terms`, `/privacy`, `/judge/payment/callback`) در دو اندازه صفحه انجام
  نشد؛ سندباکس این نشست اجازه لانچ Chrome/DNS به دامنه زنده را نداد.
- اصلاح میدل‌ور/هدر روی سرور دیپلوی نشده؛ تا دیپلوی، تست `damages-redirect.spec.ts`
  روی production شکست می‌خورد (رفتار قدیم هنوز فعال است).
- ۳ بسته توکن هنوز واقعاً وصل نیستند (فقط «به‌زودی»)؛ نیاز به تصمیم مالک: یا plan_type
  جدید در `get_calculated_pricing()` اضافه شود، یا از UI حذف شوند.
